## Phase A — Diagnostics (~15 min, no changes)

1. **Lemonade**: `lemonade-server --version`; then `lemonade-server pull Qwen2.5-3B-Instruct-Hybrid` (catalog listing does not imply downloaded weights). Retry a single chat against `:13305` with the other backends **stopped** (rules out memory contention). If it still fails: check Lemonade logs (`%LOCALAPPDATA%\lemonade*` or the server console) for the two known failure signatures — missing `onnxruntime_providers_ryzenai.dll` (Lemonade issue #1072) and NPU driver version mismatch (recommended vs installed, e.g. 32.0.203.240) — and check Device Manager → NPU driver version.
2. **GPU hardware reality check**: `nvidia-smi` in a terminal. Works → NVIDIA path (CUDA wheel). Fails → AMD iGPU/Radeon path (Vulkan wheel). This decides Phase B.2.

## Phase C — Code fixes (branch `codex/multi-engine-routing`)

**C.1 Fallback-chain failover (now with a measured cost: 20/20 grounded_qa requests died that a `hybrid→gpu→npu→cpu` chain would have completed).** In `runtime.py`, wrap tool-plan/final/repair generation in a loop over `_ordered_backend_plan`: on `model_backend_unavailable`/`model_request_failed`, advance to the next binding; record real `attempts[]`, `fallback_attempted`, `fallback_reason` (fields already exist in the execution payload, currently hardcoded). Unit test with a failing first client.

**C.2 GPU-offload honesty guard (provider).** After llama.cpp load: call `llama_cpp.llama_supports_gpu_offload()`; if `n_gpu_layers > 0` and unsupported, emit `gpu_layers_requested_but_cpu_only_build` in warnings + diagnostics. Log an offload summary line at load (and gate llama.cpp `verbose` on an env var) so this class of issue can never hide again.

**C.3 Deterministic tool prompts.** Split `_tool_result_payload` into the full record (traces/evidence, unchanged) and a prompt-facing record without `started_at`/`finished_at`/`sandbox`. Acceptance: `tool_required_short` goes 10/10 identical.

**C.4 Reliable non-thinking mode for Qwen3 on llama.cpp.** When `allow_reasoning=False` and the model is Qwen3 on the llamacpp path, build the ChatML prompt directly with an assistant prefill of an empty think block (`<think>\n\n</think>`) and `<|im_end|>` stop — the documented reliable method; the `/no_think` soft switch stays as a fallback for other paths. (Template-level `enable_thinking:false` is the llama-server/API mechanism and isn't reachable through `create_chat_completion`'s generic chatml handler.)

**C.5 Slim the system prompt.** Keep behavioral instructions; drop route confidence/metadata JSON from model-visible text (stays in traces). Saves ~90 tokens/request and stops the parroting.

**C.6 Benchmark script.** Honor per-case `max_tokens` (agentic case 512); add `-MaxTokens` guidance for thinking models (1024+); add an automatic determinism check per case (distinct-output count) so regressions self-report.

## Phase E — One-command benchmark gauntlet (gap: manual start/run/stop)

`scripts/Invoke-HarnessBenchmarkGauntlet.ps1` — single entry point:

1. **Preflight** (fail fast, before any process starts): config parse + expected devices/ports; Lemonade reachable and hybrid model present in its catalog; GPU wheel offload capability (`llama_cpp.llama_supports_gpu_offload()` via the venv python); ports free or already-healthy.
2. **Bring-up**: model backend fleet (npu/cpu) + GPU backend with offload layers + `Start-HarnessBackend` with health wait.
3. **Run**: N seeded benchmark runs (default 2 × seed 42, `-MaxTokens 1024`).
4. **Teardown in `finally`**: harnessd + fleet + GPU backend stopped even when a step throws; `-KeepStackRunning` opts out.
5. **Report**: calls `scripts/gauntlet_report.py` over the run directories → combined scoreboard (json + markdown).
6. `-DryRun` prints every action without starting anything (first-run safety since the orchestrator cannot be executed in the development sandbox).

## Phase F — Quality scoring (gap: "how well" ≠ speed only)

`scripts/gauntlet_report.py` + `scripts/benchmark-quality-checks.json` (post-hoc over run JSONs, so the PS benchmark script stays untouched and the logic is unit-testable):

- Answer extraction: strip `<think>…</think>`; an unterminated think block ⇒ `thinking_only` (automatic quality fail — the truncation failure mode becomes measurable).
- Per-case checks from JSON config: `contains` / `regex` / `nonempty_answer` applied to the post-think answer (e.g. tool case must contain `43`; agentic case must mention the twist and checklist).
- Aggregates: per-device scoreboard — p50 latency, avg tok/s, success %, fallback %, truncation %, **quality pass %** — plus per-case cross-run determinism (distinct outputs within runs, first-iteration equality across runs).
- Verification: reporter run against the real seeded-run-01/02 data (expected: quality ≈ 0% due to think-truncation — demonstrating the metric catches exactly what Phase D fixes).
